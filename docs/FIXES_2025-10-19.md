## Additional Fix: Mouse Rotation Not Working (Part 2)

### Problem (Still Present After First Fix)
Mouse still behaving like keyboard - moving camera instead of rotating view.

### Root Cause
**Wrong camera type!**

`UniversalCamera` is designed for **touch/gamepad** devices where mouse acts like a joystick:
- Mouse movement = Camera position movement (like gamepad stick)
- Touch = Movement + rotation
- Gamepad = Full control

This is NOT the expected desktop FPS behavior where:
- Mouse = Look around (rotate view)
- Keyboard = Move position

### Solution
Changed camera type from `UniversalCamera` to `FreeCamera`:

```javascript
// BEFORE (wrong camera type)
this.camera = new BABYLON.UniversalCamera("camera", position, scene);
// Mouse acts like movement joystick ❌

// AFTER (correct camera type)
this.camera = new BABYLON.FreeCamera("camera", position, scene);
// Mouse rotates view (look around) ✅
```

### Camera Type Comparison

| Camera Type | Mouse Behavior | Use Case |
|-------------|----------------|----------|
| **UniversalCamera** | Movement (joystick) | Touch devices, tablets, gamepads |
| **FreeCamera** | Rotation (look around) | Desktop FPS games ✅ |
| **ArcRotateCamera** | Orbit around target | 3D model viewers |
| **FollowCamera** | Follows target mesh | Third-person games |

### Desktop FPS Controls (Now Correct)
- **Mouse drag**: Look around (horizontal + vertical rotation)
- **WASD**: Move forward/back, strafe left/right
- **Arrow keys**: Same as WASD
- **E/Q**: Move up/down
- **Scroll wheel**: Zoom (FOV adjustment)

## Additional Fix: Mouse Rotation Not Working

### Problem (Discovered During Testing)
Mouse movement did not rotate the camera in desktop mode.

### Root Cause
**Improper input setup order**:
1. `attachControl()` was called before configuring input sensitivity
2. `angularSensibility = 2000` set AFTER attachment (may not take effect)
3. Value of 2000 is very insensitive (higher number = less sensitive)

### Solution
Reordered camera initialization to set inputs BEFORE attaching controls:

```javascript
// BEFORE (wrong order)
this.camera.attachControl(this.canvas, true);  // Attached first
this.camera.keysUp = [87, 38];                 // Keys set after
this.camera.angularSensibility = 2000;         // Sensitivity set after

// AFTER (correct order)
this.camera.keysUp = [87, 38];                 // Keys set first
this.camera.angularSensibility = 1000;         // Sensitivity set first (lower = more responsive)
this.camera.attachControl(this.canvas, true);  // Attach last
```

### Proper Camera Setup Order
1. ✅ Create camera with position
2. ✅ Set target
3. ✅ Configure keyboard controls (keysUp, keysDown, keysLeft, keysRight)
4. ✅ Configure mouse sensitivity (angularSensibility, inertia)
5. ✅ **THEN** attach controls to canvas
6. ✅ Set other properties (speed, gravity, collisions)

### angularSensibility Values
- **2000** (old): Very insensitive, barely noticeable mouse movement
- **1000** (new): More responsive, comfortable rotation speed
- **500**: Very sensitive (if user wants faster rotation)

### Files Modified
- `js/club_hyperrealistic.js` lines 317-342

### Expected Result
- Mouse drag/movement now rotates camera view (horizontal + vertical)
- Arrow keys + WASD move camera position
- Smooth rotation with inertia

## Additional Fix: Front Wall Raycast Alignment

### Problem (Discovered After Initial Fix)
Mirror ball spots were still invisible on front wall despite correct wall position.

### Root Cause
**Coordinate mismatch between wall geometry and raycast**:
- Front wall box: center at `z=2`, depth `0.5`
- Inner face (club-facing): `z = 2 - 0.5/2 = 1.75`
- Surface definition: `z=1.73` (correctly positioned)
- **Raycast was using**: `z=1.98` ❌ (wrong!)
- Spots were positioned at surface definition `z=1.73` but raycast targeted `z=1.98`
- Result: Spots appeared off the wall surface, invisible

### Solution
```javascript
// BEFORE
const t = (2 - ballPos.z) / dirZ;  // Wrong: box center
hitPos = new BABYLON.Vector3(x, y, 1.98);  // Wrong: arbitrary offset

// AFTER
const t = (1.75 - ballPos.z) / dirZ;  // Correct: inner face
hitPos = new BABYLON.Vector3(x, y, 1.73);  // Correct: matches surface definition
```

### Technical Details
Front wall geometry:
- Box center: `(0, 5, 2)`
- Box dimensions: `35m x 10m x 0.5m`
- Inner face (toward club): `z = 2 - 0.25 = 1.75`
- Surface definition (mirrorReflectionSpots): `z = 1.73` (slight offset for disc placement)

Raycast now targets `z=1.75` (actual wall face), spots positioned at `z=1.73` (on surface).

### Files Modified
- `js/club_hyperrealistic.js` line 3202-3214

### Expected Result
- Mirror ball spots now visible on front wall from inside club
- Spots aligned with wall surface (not floating)
- Normal `(0,0,-1)` ensures discs face inward (correct orientation)
